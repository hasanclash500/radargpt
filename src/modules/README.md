# ماژول‌های اختیاری دیوساز

این پوشه مرز بین هسته دیوساز و سرویس‌های قابل تعویض است.

## قانون اصلی

SDK یا کد providerهای خارجی (پیامک، درگاه پرداخت، CRM و غیره) نباید مستقیماً
داخل صفحات اصلی، منطق آگهی یا داشبورد import شود. هر قابلیت اختیاری در پوشه
مستقل خودش ساخته می‌شود و از `defineDivosazModule` استفاده می‌کند.

## نصب ماژول

1. یک پوشه مثل `src/modules/sms-auth/` بسازید.
2. ماژول را با قرارداد `DivosazModule` تعریف کنید.
3. آن را فقط در `src/modules/index.ts` یا فایل bootstrap ماژول‌ها register کنید.
4. مدیر از پنل «ماژول‌ها» آن را فعال/غیرفعال می‌کند.

## ورود پیامکی

برای ورود/ثبت‌نام پیامکی از `authEntries` استفاده کنید. کامپوننت provider
داخل صفحه ورود در جایگاه از قبل آماده‌شده نمایش داده می‌شود. این کار اجازه
می‌دهد provider عوض شود بدون اینکه فرم رمز عبور یا Router اصلی بازنویسی شود.

## پرداخت ثبت آگهی

از `listingSubmission.beforeSubmit` برای ساخت سفارش/پرداخت/کنترل سهمیه استفاده
کنید. اگر نتیجه `allowed: false` باشد، ثبت آگهی متوقف می‌شود. داده برگشتی
`metadata` به `afterSubmit` می‌رسد تا بعد از ثبت موفق رسید یا تراکنش نهایی
شود.

## مسیر و پنل مدیریت

- `routes`: صفحه‌های مستقل ماژول
- `adminPanels`: تنظیمات ماژول در پنل مدیر
- `capabilities`: اعلام نوع قابلیت برای UI و مستندسازی

## اصل مهاجرت

ماژول اختیاری نباید فیلد provider-specific را به جدول listings اضافه کند مگر
اینکه آن فیلد واقعاً بخشی از مدل دامنه دیوساز باشد. اطلاعات اختصاصی provider
باید در جدول/فایل ماژول خودش نگهداری شود. این اصل حذف یا تعویض ماژول را امن
می‌کند.
